EOL = アップデート提供終了。更新期限は Google 公式の更新ポリシー（Pixel 6/7/Fold = 5年、Pixel 8以降 = 7年）と発売世代からの目安。正確な提供タイミングは地域・キャリアで前後する。

開発者オプション詳細（分類・項目・用途）

入口: 設定 → デバイス情報 → ビルド番号を7回タップ → 設定 → システム → 開発者向けオプション。Pixel/Android 17 を基準に、端末やOSで名称・表示有無が変わる項目は「表示される場合」として扱う。

原則: 不具合解析が終わったら USBデバッグ / ワイヤレスデバッグ / OEMロック解除 / GPU強制系 / アクティビティ破棄系 は元に戻す。メイン機で「意味は不明だが速くなりそう」という理由で変更しない。

診断・ログ

バグレポート、メモリ、実行中サービス、logcat量を確認する。問い合わせや再現証拠の中心。

ADB・PC接続

USB/Wi-Fi経由で端末を操作する。復旧・バックアップ・ログ採取に使うが、許可管理が重要。

入力・画面表示

タップ、ポインタ、レイアウト境界、アニメーションを可視化し、操作異常やUI崩れを切り分ける。

GPU・描画

GPU負荷、オーバードロー、HW overlay、色覚シミュレーションを確認する。ゲーム/動画/画面乱れ向け。

通信・Bluetooth

Wi-Fi詳細ログ、モバイル維持、Bluetooth音声/ログを確認する。Android Autoやイヤホン不調向け。

アプリ負荷試験

バックグラウンド制限、アクティビティ破棄、Shortcut制限を使い、アプリの弱点を意図的に出す。

SAFE FLOW使う前後の基本フロー
目的を決める→現在値をメモ/撮影→1項目だけ変更→再現確認→ログ保存→元に戻す
  • 端末保護: ADB許可ダイアログは自分のPCだけ許可。共有PC・会社PC・不明なUSBハブでは許可しない。
  • 変更管理: 画面録画・スクショで変更前の値を残す。複数項目を同時に変えると原因が追えない。
  • 初期化前: バグレポート、スクリーン録画、発生時刻、Android build、アプリ版本を保存する。

逆引き症状別に見る項目
  • Android Auto / 車載Bluetooth: USBデバッグでbugreport、デフォルトUSB設定、Bluetooth HCI snoop log、絶対音量を無効化、Wi-Fi詳細ログ。
  • LINE通知が来ない: 実行中のサービス、スタンバイアプリ、メモリ、バグレポート。バックグラウンドプロセス上限を変更している場合は標準へ戻す。
  • ゲームが重い/落ちる: GPUレンダリングのプロファイル、GPUビュー更新、HWオーバーレイ無効化の一時切り分け、メモリ、バグレポート。
  • タッチ異常: タップを表示、ポインタの位置。画面録画で「触っているのに反応しない/触っていないのに動く」を残す。
  • アプリクラッシュ/ANR: バグレポート、ロガーバッファサイズ、デバッグアプリを選択。自分のアプリ以外では「アクティビティを保持しない」を常用しない。
  • 復旧/ADB: USBデバッグ、USBデバッグの許可を取り消す、デフォルトUSB設定。復旧操作は下の専門TSへ。

電話 / Gmail 主要機能の対応状況と設定

「どの世代から使えるか」を明記。4a では使えない機能が判断材料になる。

通話スクリーニング（日本語対応版）

対応: Pixel 7 世代以降で段階提供 → 8a / 9a / 10a は標準搭載。4a〜6a は日本語自動応答は不可
  1. 電話アプリ → 右上メニュー → 設定
  2. 通話スクリーニング を選択
  3. 「不明な番号からの着信」で自動スクリーニングの強度を選ぶ
  4. 着信時は画面の「スクリーニング」ボタンで手動起動も可

注意: 営業電話・詐欺電話フィルタとして実用的なのは 8a 以降。EOL 端末での着信対応は迷惑電話フィルタアプリ側に依存することになりリスクが残る。

レコーダー文字起こし（日本語）

対応: Tensor 搭載機（6a 以降）。4a / 4a 5G / 5a は英語のみ・精度低
  1. レコーダーアプリで録音開始 → 自動で文字起こしタブに反映
  2. 録音一覧 → 共有 → テキストとしてエクスポート（Obsidian転記に使用可）

Gmail: 自動仕分け（フィルタ + ラベル）

対応: 全機種（サーバー側機能のため端末世代に依存しない）
  1. Gmail（Web推奨）→ 検索バー右の 検索オプション
  2. From / 件名 / キーワードで条件を指定 → フィルタを作成
  3. 「ラベルを付ける」「受信トレイをスキップ」を選択
  4. 求人・API通知・請求など、送信元ドメイン単位で分ける

Gemini / アシスタント切替

対応: Gemini標準は 8a 以降。6a / 7a はアプリ導入で切替可。4a 系は従来アシスタントのみ

トラブルシューティング（TS）

上から順に「全機種共通 → 世代固有の既知問題」。所有中の 4a の項目は必読。OSバージョン起因の症状は上の「OS別不具合マトリクス」を先に確認。ADB・復旧などPC接続を伴う手順は次の専門TSへ。

共通基本 TS フロー（全機種）
  1. 強制再起動: 電源ボタン 30秒長押し（画面フリーズ時もこれで再起動）
  2. セーフモード: 電源メニューの「電源を切る」を長押し → セーフモード。サードパーティアプリ起因かの切り分け
  3. アプリ単位: 設定 → アプリ → 対象アプリ → ストレージ → キャッシュ削除 → 改善なければデータ削除
  4. ネットワーク: 設定 → システム → リセット → Wi-Fi/モバイル/Bluetoothをリセット
  5. OSアップデート確認: 設定 → システム → ソフトウェアアップデート
  6. 最終手段: バックアップ → 初期化。復旧不能ならリカバリーモード（電源OFF → 電源+音量下 長押し）から Factory Image を sideload
4aPixel 4a — EOL + バッテリー制限問題

状態: 2023年に全アップデート終了。さらに2025年1月の最終「バッテリー性能アップデート」で、一部個体はバッテリー容量・充電速度が意図的に制限された（発火リスク対策）。対象個体はGoogleが交換/返金プログラムを提供していた。

  • 電池の減りが急に悪化した場合: 故障ではなく上記アップデートの仕様の可能性が高い。設定 → バッテリー → 使用状況で確認
  • セキュリティ: 更新が来ないため、銀行・決済・仕事用アカウントのログインは非推奨。検証用・音楽プレーヤー・室内サブ機に限定
  • 膨張チェック: 背面パネルの浮き・画面の押し上げが出たら即使用中止（リチウム電池の膨張兆候）
  • 延命するなら: 非公式ROM含め、安全に延命する公式手段は実質ない
4a5G/5a4a (5G)・5a (5G) — EOL 共通
  • 両機とも Snapdragon 765G。動作自体はまだ実用域だがセキュリティ更新なし → 4a と同じ「サブ機限定」判断
  • 5a は電源ボタン陥没・膨張報告が比較的多い世代。中古購入は非推奨
6aPixel 6a — 指紋認証・発熱・モデム
  • 画面内指紋の精度が低い: 同じ指を角度を変えて2回登録すると改善。保護フィルムは指紋対応品のみ
  • 発熱・電池持ち: Tensor G1 世代共通。優先ネットワークを4Gにすると改善する場合あり
  • 通信が不安定: G1世代のモデム個体差。機内モードON/OFF → SIM再挿入 → ネットワークリセットの順で切り分け
  • 期限: 2027年7月でアップデート終了。残り約1年、買い替え計画を先に立てる
7aPixel 7a — 発熱・ワイヤレス充電
  • 充電中の発熱: ケース装着のままワイヤレス充電すると温度制御で充電が止まることがある。有線を基本に
  • 画面のちらつき報告: 明るさ自動調整OFF + 更新適用で改善例多数
  • 期限: 2028年5月まで。中古で買うならこの世代が実用下限
8a〜10aPixel 8a / 9a / 10a — 現役世代
  • 共通: 7年保証世代。問題発生時はまず月例アップデート適用 → 共通TSフロー → OS別マトリクス確認
  • 8a: 画面の緑かぶり報告はアップデートでほぼ解消済み。設定 → ディスプレイ → 画面の色味で微調整可
  • 9a: 一部ロットでバッテリー関連の出荷前対策があった世代。購入時はGoogleストアのサポート告知を確認
  • 10a: Tensor G4継続のマイナー更新世代。背面フラット化で卓上安定。GPU性能はG5より高い逆転現象があり、ゲーム用途では10無印より有利な場面もある
  • リカバリー: この世代は「修復モード」(Repair Mode) 搭載。修理に出す前に 設定 → システム → 修復モード でデータを隠せる

専門TS（基本 → 診断 → ADB → 復旧）

レベル順に並べた実務手順集。Lv2以降はPC（Mac）接続が前提。DATA LOSS 付きの操作はデータ消去を伴うため、実行前にバックアップ必須。

Lv0基本（端末単体で完結）

強制再起動・セーフモード・キャッシュ削除・ネットワークリセットは上の「トラブルシューティング → 基本TSフロー」を参照。ここでは重複させない。迷ったら必ずLv0から順に試す。

Lv1診断（root不要・無害）
  • 開発者オプション有効化: 設定 → デバイス情報 → ビルド番号を7回タップ。以降のLvで前提になる
  • バッテリー状態: 設定 → バッテリー → バッテリーの状態（対応世代）。劣化度と充電回数の目安を確認
  • 通信テストメニュー: 電話アプリで *#*#4636#*#* — 電波強度・優先ネットワーク・Wi-Fi詳細 UNVERIFIED
  • IMEI確認: *#06#（中古売却・キャリア問い合わせ時に必要）
  • バグレポート取得（端末単体）: 開発者オプション → バグレポートを取得 → 通知から共有。サポート問い合わせ時の添付用
Lv2ADB（PC接続・非破壊）

準備（Mac側・初回のみ）:

brew install android-platform-tools
# 端末側: 開発者オプション → USBデバッグ ON → ケーブル接続 → 「許可」

基本診断コマンド:

adb devices                                    # 接続確認（deviceと出ればOK）
adb shell getprop ro.build.version.release     # OSバージョン
adb shell getprop ro.build.version.security_patch  # セキュリティパッチ日付
adb shell getprop ro.product.device            # コードネーム確認
adb shell dumpsys battery                      # バッテリー詳細
adb bugreport ~/Desktop/bugreport.zip          # 完全ログ取得

実務ユーティリティ:

adb shell pm list packages | grep -i 対象名    # パッケージ名の特定
adb shell pm uninstall --user 0 パッケージ名   # プリインアプリの無効化(復元可)
adb pull /sdcard/DCIM ~/Desktop/pixel-photos   # 写真一括退避
adb shell screenrecord /sdcard/rec.mp4         # 画面録画（Ctrl+Cで停止）
Lv3復旧（リカバリー / sideload / Factory Image）
この階層は操作を誤るとデータ消去・文鎮化に直結する。実行前フルバックアップと、下のコードネーム表で機種一致の確認を必須とする。

A. リカバリーモード起動（起動不能時の入口）:

電源OFF → 電源 + 音量下 長押し → bootloader画面
音量キーで「Recovery mode」選択 → 電源キーで決定
「No command」表示 → 電源を押しながら音量上を一回

B. OTA sideload — データを消さずにOSを上書き修復（ブートループ時の第一選択）:

リカバリー画面で「Apply update from ADB」を選択
# Mac側: 機種のOTAイメージを https://developers.google.com/android/ota から取得
adb devices        # sideload と表示されることを確認
adb sideload ota_image.zip

C. Factory Image 全書き込み DATA LOSS — 最終手段:

# https://developers.google.com/android/images から機種コードネーム一致の版を取得
adb reboot bootloader
fastboot devices
./flash-all.sh     # 全データ消去して工場出荷状態に

警告: ブートローダーアンロック（fastboot flashing unlock）は全データ消去に加え、Play Integrity 判定が失敗し銀行・決済・一部ゲームアプリが恒久的に使用不能になる UNVERIFIED。実施してよいのはEOL検証機（4a）のみ。メイン機では絶対に行わない。

ARB（anti-rollback）該当機種の注意 VERIFIED: ブートローダーの anti-rollback カウンタが増加したビルド以降を適用済みの機種では、それより前のビルドの sideload / Factory Image 書き込みで起動不能（両スロット不一致でハードブリック）に至る。該当ビルド — BP1A.250505.005（2025-05: Pixel 6/6 Pro/6a・8/8 Pro/8a、Android 15へ巻き戻し不可）/ CP1A.260505.005（2026-05: Pixel 10系、Android 16へ巻き戻し不可）。復旧作業前に ビルド番号辞書（ビルド番号で引く） で手元のビルドIDを検索し、ARB警告の有無を確認すること。
